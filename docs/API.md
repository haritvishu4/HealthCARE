# Care Intake API

The definitive request schemas are generated by FastAPI at `/openapi.json`; interactive documentation is at `/docs` in development.

All `/api/*` routes require `Authorization: Bearer <access-token>`. Local development uses the generated `DEV_AUTH_TOKEN`; the loopback frontend proxy injects it server-side. Production uses an asymmetric Supabase JWT. `GET /health` is public and reports database connectivity only. API keys never belong in browser JavaScript.

## Intake

`POST /api/patient/intake`

```json
{
  "patient": {
    "name": "Fictional Patient",
    "age": 32,
    "gender": "Female",
    "symptoms": "Patient reports feeling unwell",
    "duration": "Two days",
    "medical_history": "Not yet provided",
    "allergies": "Not confirmed",
    "current_medicines": "Not confirmed",
    "additional_details": {},
    "mode": "General"
  },
  "consent": true
}
```

Response: `patient_id`, `consultation_id`, `version`, `status`. Preserve the returned IDs. For a new visit, send the existing `patient_id` without `consultation_id`. To update the same visit, also send `consultation_id` and its current `expected_version`.

Patient information is stored encrypted. Old consultations keep their own patient-detail snapshots. Changing an intake invalidates its current AI analysis/review; already generated PDFs remain immutable historical drafts.

## Audio

`POST /api/audio/transcribe` — multipart form with:

| Field | Value |
| --- | --- |
| `file` | WAV, WebM, OGG, MP3, M4A, or FLAC bytes |
| `consultation_id` | Owned consultation ID |
| `expected_version` | Current integer version |
| `language` | `hi-IN`, `en-IN`, another `/api/system` language, or `unknown` |

Returns `text`, `language_code`, `provider`, and the updated `version`. The validated transcript is appended to the consultation. Original audio is not retained by this backend. Provider retention is governed by your provider account/contract. The existing mic records at most 25 seconds per segment; long-recording batch processing is not implemented.

## Documents

`POST /api/document/upload` — multipart `file`, `consultation_id`, `expected_version`.

Returns `id`, `name`, `extracted_text`, `text`, `document_type`, `confidence`, `provider`, and `version`. `confidence` is `null` because the selected extraction provider does not supply a calibrated confidence value here. Document type is a text heuristic, not a medical interpretation.

PDF text extraction is local if every page contains sufficient text. Scanned or mixed pages are sent to OCR.space. An unreadable page fails the upload rather than silently dropping that page. Text limits, file signatures, image dimensions, page count, and filename normalization are checked.

`GET /api/document/{id}/download` downloads the authenticated original. `DELETE /api/document/{id}?expected_version=N` removes the document and invalidates the current analysis; historical PDFs are retained.

## Clinical assistance

`POST /api/ai/analyze`

```json
{
  "consultation_id": "ID_FROM_INTAKE",
  "expected_version": 3,
  "transcript": "",
  "ocr_text": ""
}
```

The server retrieves current patient details, saved transcripts, extracted documents, and up to five visible earlier visits. Optional additional text belongs to this analysis request. Names/contact fields are excluded from the dedicated patient object sent to Gemini; free-text documents can still contain identifying information.

Response includes:

```json
{
  "summary": "Clinical assistance draft",
  "symptoms_analysis": "Patient-reported facts and uncertainties",
  "possible_conditions": [],
  "severity": "insufficient_information",
  "recommended_tests": [],
  "precautions": [],
  "doctor_notes": "Physician approval is required",
  "missing_details": [],
  "follow_up_questions": [],
  "physician_approval_required": true,
  "analysis_id": "SERVER_GENERATED_ID",
  "version": 4,
  "provider": "gemini",
  "cached": false
}
```

Severity is a suggested **review priority**, one of `urgent_review`, `prompt_review`, `routine_review`, or `insufficient_information`. It is not a validated risk score. JSON structure is validated before saving; clinical correctness still requires physician review. Identical input context may reuse a previously validated analysis for the same consultation.

## Summary, doctor review, sharing

| Endpoint | Request / behavior |
| --- | --- |
| `GET /api/consultation/{id}` | Current input, extracted evidence, AI analysis, user amendments, review, version |
| `GET /api/consultations?offset=0&limit=25` | Paginated owned visits and visits assigned to the authenticated doctor |
| `GET /api/doctor/dashboard?status=all&offset=0&limit=10` | Doctor-only counts and paginated consultation summaries; owned or explicitly assigned visits only |
| `PATCH /api/consultation/{id}/summary` | `expected_version`, `summary` object of amended field labels/text; changed amendments invalidate earlier review |
| `POST /api/consultation/{id}/review` | `expected_version`, `summary`, `decision` (`accept`/`reject`), optional `doctor_notes`; doctor role required |
| `POST /api/consultation/{id}/share` | Owner only: `expected_version`, `doctor_id` (trusted Supabase subject, or `null` to revoke) |
| `PATCH /api/consultation/{id}/consent` | Owner only: `expected_version`, `consent`; revoking consent stops external processing and removes assigned doctor access |
| `GET /api/patients?offset=0&limit=50` | Owned patient profiles |
| `GET /api/patient/{id}/history?offset=0&limit=50` | Visible consultation timeline and authenticated historical draft download URLs |

A share permits access only when the target JWT also has the server-managed doctor role. It does not send a notification. Revoking access cannot recall a file someone already downloaded. Ending the local device session clears browser memory; it does not delete medical records.

The dashboard accepts `status=all|pending|reviewed|rejected|draft`, a nonnegative `offset`, and `limit=1..50`. Its response contains `stats` (`total`, `pending`, `reviewed`, `rejected`, `draft`), `items`, `offset`, `limit`, `has_more`, and `total_matches`. Counts cover all accessible consultations; `total_matches` covers the selected status. Items contain visit ID, patient name/age/gender, mode, status, timestamps, and `has_analysis`, ordered by most recent update. `pending` means a current analysis exists and has not been accepted/rejected; `draft` means no current analysis. Counts inspect encrypted snapshots within the doctor's access scope, so response time grows with that doctor's visit history.

## PDF draft

`POST /api/prescription/generate`

```json
{
  "consultation_id": "ID_FROM_INTAKE",
  "analysis_id": "ID_FROM_ANALYZE",
  "expected_version": 4
}
```

Response: `{"id":"DRAFT_ID","pdf_url":"/api/prescription/DRAFT_ID/download","draft":true}`.

The server uses its stored analysis and patient snapshot. It does not accept an arbitrary client-supplied AI report. An unchanged snapshot returns the existing draft ID. A changed snapshot creates a new version in history. The PDF is encrypted in the database rather than exposed through a public static `pdf_path`.

`GET /api/prescription/{id}/download` returns `application/pdf` with an attachment filename. The owner and assigned doctor can download with authentication. A bare URL is not a public sharing link. The browser download can be printed or intentionally shared by its user.

## Errors and limits

| Status | Meaning |
| --- | --- |
| 401 | Missing, invalid, or expired bearer token |
| 403 | Consent or doctor role required |
| 404 | Missing resource or resource outside the caller's scope |
| 409 | Stale version / conflicting or invalidated analysis |
| 413 | File or request too large |
| 415 | Unsupported or invalid file content |
| 422 | Invalid input, unreadable document, or unsupported PDF character |
| 429 | Local per-user request limit reached; Retry-After is supplied |
| 502 | Invalid/incomplete provider output or provider processing failure |
| 503 | Missing key, provider quota/auth/network error, or database unavailable |

Errors return a safe `detail` and may include `provider` or validation field names. They do not echo patient payloads, stack traces, or provider keys. The API allows 60 requests/minute per account, with additional speech (20), OCR (10), and analysis (8) limits. Provider concurrency is bounded per process. Production edge limits and worker isolation belong in your deployment.
